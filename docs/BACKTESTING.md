# Alphora PR #2: offline historical data and backtesting foundation

This is a **research prototype**, not a production backtester or order execution engine.

## Data
Use CSV with columns `date,open,high,low,close,volume`; strict ascending unique dates, finite positive prices, valid OHLC and nonnegative volume. Malformed CSV row widths (missing or extra fields), blank records (including trailing blank rows), and malformed quoting are rejected as `BAD_CSV_ROW` rather than silently omitting potentially missing sessions, swallowing records, or surfacing an unhandled parser exception. An empty file is rejected as `CSV_SCHEMA`. CSV date fields must use canonical `YYYY-MM-DD` (not compact or ISO-week dates); volumes must be unsigned ASCII decimal integers with no plus sign, whitespace, underscores or leading zeros (except `0`). Python's permissive date/integer parsing otherwise silently normalizes vendor input. OHLC prices must be unsigned canonical ASCII decimal values such as `100`, `100.25`, or `0.50` (no exponent notation, embedded underscores, Unicode digits, signs, leading zeros, or surrounding whitespace); this avoids silent `Decimal` normalization. Zero-volume rows remain valid OHLCV *input data* for inspection, but the underlying offline `backtest` now refuses any zero-volume session with `ZERO_VOLUME_RESEARCH_BACKTEST_UNSUPPORTED`. The SPY comparator additionally checks the **entire supplied SPY history**, including lookback warm-up sessions that are omitted from the benchmark evaluation window, before slicing; previously a standalone backtest could fabricate an opening fill. The separate pinned replay gate also rejects zero-volume histories. This is deliberately conservative (even a zero-volume first bar is rejected), not an exchange-halt, opening-auction liquidity, or stale-quote model. Strategy lookback is strictly an integer >=2; bool, fractional or string lookbacks fail closed. No online market-data provider has been connected. Inputs require external provenance checks, vendor licensing, adjusted/unadjusted consistency, exchange calendars, splits, dividends, delisted securities and survivorship-bias mitigation before reliable market conclusions.

## Strategies
`trend`: closing price above trailing SMA; `momentum`: closing price above close 20 sessions ago; `mean_reversion`: close below prior-20-session mean; `buy_hold`: always own when affordable.

## Model
Signals use **observed closes up to t-1**, orders fill at next open t. Cash-only, long-only, whole shares, maximum 10% instrument notional at entry, fixed per-side transaction cost (default 5 basis points). Equity measured at closing prices. Returns, maximum drawdown, zero-risk-free-rate annualized Sharpe, transactions and full equity curve are calculated. Simulated cash movements, transaction-cost multiplications and position market-value additions now fail closed with `UNREPRESENTABLE_BACKTEST_LEDGER_ARITHMETIC` when Decimal arithmetic would silently round or overflow (for example, subtracting $1 from an extreme 1e30 cash balance under a fixed 28-significant-digit ledger precision). Ledger acceptance is isolated from a caller's ambient Decimal precision so the same synthetic data cannot pass at precision 80 and fail at precision 28. This protects the primitive's financial ledger against mathematically unrepresentable inputs; fractional position sizing and return/Sharpe ratios still use simplified rounded research calculations, not an audited execution engine.

## Deliberate limitations
Single instrument; no data downloader, splits/dividends, delisting payouts, session/calendar validation, slippage or spread model beyond simplified bps, stop handling, multi-asset allocation, portfolio daily halt, partial fills, walk-forward runner or real brokerage. In particular the PR #1 0.5% planned trade stop risk and 2% daily shutdown are **not** enforced by this research-only simulator: integrating these controls is required before paper orders. The 10%-exposure buy-hold reference is not equivalent to fully invested SPY.

No claimed alpha, trained ML model, real brokerage access or live trading capability.

Input parsing ensures canonical CSV formatting, **not content authenticity**. A price changed from `100` to `101` in an otherwise well-formed row remains syntactically valid. Only independently pinned artifact checksums, trusted delivery/version evidence and expected row/session manifests can detect such tampering or missing valid-format observations; none are provided by this primitive loader.
